# 補標點:用哪個本機小模型、怎麼保證不改字

2026-10-21。背景:Breeze-ASR-25 的輸出幾乎沒有標點。VoiceInk 的「AI 潤稿」可以把辨識結果交給語言模型處理。條件:本機執行、快、省資源、**一定輸出繁體、不能改字**。

## 先決定:繁體由程式保證

小模型(特別是中國廠商的)常把繁體改成簡體,也會換字、漏字、改寫句子,甚至把逐字稿當成問題來回答。光靠指示詞擋不住。所以:

1. 模型只負責建議標點。
2. 程式把模型輸出和原文逐字對齊(兩邊先用 macOS 內建的 ICU `Traditional-Simplified` 轉成同一種字體再比),只把標點插回原文。
3. 對得上的字少於 50% → 整句回傳原文;否則只採用「前後兩個字在原文裡也相鄰」的標點。

這樣模型選擇只要看「標點補得好不好」和「快不快」。實作:v1 是 Python(`punct.py`,在私人 repo `voiceink-zhtw-lmstudio`),v2 是 [`ZhTWPunctuation.swift`](../../VoiceInk/Features/ZhTW/ZhTWPunctuation.swift),兩者用同一組案例驗證結果一致(`scripts/test-punctuation.sh`)。

## 候選

| 模型 | 大小(MLX 4bit) | 說明 |
|---|---|---|
| Qwen3.5-2B | 1.75GB | 2026-03 推出,有 MLX 版;本身偏簡體 |
| Qwen3.5-4B | 3.06GB | 5B 以下最強 |
| Breeze2-3B(Llama 3.2 基底) | 2.05GB | 聯發科,繁中特化;2025-01 推出,MLX 版是社群轉檔 |
| Gemma 4 E2B / E4B | 4.3 / 6.8GB | 內含影像、音訊模組,補標點太重,沒測 |
| TAIDE 8B 等 | 5GB 以上 | 補標點用不到這麼大,沒測 |

## 測試方法

M1 Pro 32GB、LM Studio 0.4.10(MLX 引擎 1.13.1)。12 句實際聽寫內容(Breeze-ASR-25 輸出、沒有標點),每句跑 3 次取中位數,temperature 0,`max_tokens = 字數×2+32`。範例用多輪對話給(系統指示 + 3 組 user/assistant)。

## 結果

| | Breeze2-3B | Qwen3.5-4B | Qwen3.5-2B |
|---|---|---|---|
| 記憶體 | 2.05GB | 3.06GB | 1.75GB |
| 延遲中位數 | **0.45 秒** | 1.25 秒 | 0.60 秒 |
| 最慢一句 | 0.77 秒 | 1.71 秒 | 0.82 秒 |
| 標點品質 | 好,偶爾逗號多 | **最好** | 最差(句號放錯、漏句號、問句用句號) |
| 模型偷改的字(程式會丟掉) | 3 | 1 | 2 |
| 退回原文 | 0 | 0 | 0 |

## 建議

**Breeze2-3B。** 最快、品質接近 4B,而且是繁中特化。Qwen3.5-4B 標點最準,但每次多等約 0.8 秒、多佔 1GB。

## 過程中踩到的

- **Qwen3.5-4B 的對話範本預設開思考模式**(2B 的剛好相反):`max_tokens` 全花在思考,12 句全部空白。LM Studio 的 API 關不掉(`chat_template_kwargs`、`reasoning_effort`、`/no_think` 都無效),只能改模型資料夾裡的 `chat_template.jinja`。
- **Breeze2 在最短的句子照抄範例的答案** → 範例裡加一個短句就好了。
- **Breeze2 會改寫對話口吻的句子**(把「我」改成「你」、換掉句首),原本整句退回原文 → 加一個「你、我」對話的範例,合併改成只取相鄰位置的標點。改完後 16 句全部有標點、0 句退回原文,延遲中位數 0.39 秒。
- **LM Studio 在 Mac 上只提供 MLX 引擎**,沒有 llama.cpp,GGUF 模型不能用。

## 範例的給法

VoiceInk Refine 的 XPC 引擎只收一段系統指示字串。測試「範例全部寫進系統指示」的效果(同樣 16 句):

| 範例給法 | 沒補上標點 | 模型改的字 |
|---|---|---|
| 多輪對話(user/assistant) | 0 句 | 2 |
| 寫在系統指示裡 | **7 句** | **297**(改寫、回答問題) |

所以 v2 把範例包成 JSON 交給 XPC,由引擎展開成多輪對話(見 [2026-10-21-single-app-via-refine.md](2026-10-21-single-app-via-refine.md))。
